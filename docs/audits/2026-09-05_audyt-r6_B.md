## 1. M-01 — orphan natychmiast do żywych

**Lokalizacja:** `state/mod.rs` — `settle_position_at`, `redistribute_to_live`, `forfeit_position`.

### Mechanizm

Po wyliczeniu `pending` (do capu) i `orphan` (live index − cap):

1. `total_shares -= shares` wychodzącego,
2. `redistribute_to_live(orphan)`:
   - `total_shares == 0` → `xnt_undistributed += orphan` (zasada pustego koszyka),
   - w przeciwnym razie `xnt_reward_index += orphan * PRECISION / total_shares` (floor).

`forfeit_position`: `settle_position` (cap = live index ⇒ orphan = 0) + `redistribute_to_live(pending)` — cały naliczony XNT wychodzącego idzie do pozostałych.

### Atak, który znika

Wejście dużym kapitałem *po* dacie, z której pochodzi orphan, a *przed* następnym `close_day`, żeby zgarnąć bufor. Bufor historyczny przy niepustej puli już nie rośnie z orphana.

### Kaskada

Pozycja dojrzała, ale jeszcze nie settlowana, nadal jest w `total_shares`, więc może dostać bump. Przy jej własnym settle cap jest jej `end_epoch` — nadwyżka znów jest orphanem i spływa dalej. Zbieżne; nikt z capem poniżej bumpa nie wypłaca cudzego orphana.

### Dust

Dwa floory `(cap−debt)×s/P` + `(live−cap)×s/P` vs jeden `(live−debt)×s/P` mogą zgubić 1 jednostkę. Property test `test_r6_property_konserwacja_xnt_losowe_sekwencje` (40 ziaren × 120 kroków) asercuje `paid + pending_live + undistributed + basket ≤ funded` oraz ograniczony dust. Kierunek zaokrągleń wyłącznie w dół — bez wektora „w stronę atakującego”.

### Werdykt M-01

**Czyste / naprawione.** Inwariant §2 z R5 nadal stoi; alokacja *wtórna* orphana jest teraz zgodna z „żywi w chwili settle”, nie z „kto stoi przy następnym close”.

## 2. F-01 — griefing rezerwacją ANL

**Lokalizacja:**

- `anl-math`: `MAX_PERIOD_DAYS_FLEXIBLE = 365`, `EARLY_EXIT_COOLDOWN_SECS` = 3 doby / 3600 s (`test-periods`)
- `stake.rs`: dodatkowy strop dla `PoolType::Flexible`
- `lifecycle.rs` `unstake_early`: `now >= start_ts + EARLY_EXIT_COOLDOWN_SECS`
- `errors.rs`: `EarlyExitCooldown` na końcu enumu (kody wcześniejsze bez zmian)
- strażnik produkcji w `production_constants_guard`

### Stary wektor

Rezerwacja ANL = `amount × APY × dni / rok`. Flexible 3650 dni × 8% ≈ 80% kapitału w Reward Vault, `unstake_early` bez kosztu → rotacja pozycji 1,25× wolnej rezerwy blokowała `stake` wszystkim.

### Mitigacja

| Dźwignia | Skutek |
|---|---|
| Flexible ≤ 365 dni | rezerwacja ≤ 8% kapitału pozycji |
| cooldown 3 dni | każdy cykl ataku bounduje kapitał ≥ 3 dni |
| Genesis bez zmian | brak `unstake_early`; 10 lat × 20% to lock, nie flash-grief |

Koszt ataku z ~0 do „8% puli nagród na 3 dni na cykl, przy kapitale 12,5× celowanej rezerwy”. Nie eliminuje griefingu przy bardzo dużym kapitale i pełnym vaultcie — **zmienia go z darmowego DoS w kosztowny lock**. To akceptowalny residual produktowy (Low), nie High.

`InvalidPeriod` w enumie nadal mówi `7..=3650 days` — komunikat nie rozróżnia Flexible. Dług UX, nie logika.

### Werdykt F-01

**Naprawione jako mitigacja.** WP musi opisać cooldown 3 dni i strop 365 dni na Flexible (zmiana semantyki względem „wyjście w każdej chwili”).

## 3. F-02 — klucze (organizacyjne)

Jeden hot key = upgrade authority + protocol authority + operator, wg `CHANGES-AFTER-ROUND6.md`.

On-chain: operator może tylko fundować; authority pauza / `set_operator` / init. Brak `withdraw` z vaultów. Kompromitacja upgrade authority to wymiana programu — **poza modelem instrukcji**.

**Przed mainnetem (blocker operacyjny, nie freeze logiki):** upgrade → multisig ≥ 2/3 + timelock (docelowo immutable); rozdział trzech ról; alerty na `pause` / `set_operator` / upgrade / `fund_rewards`.

## 7. Ścieżki sprawdzone w tej rundzie

- `redistribute_to_live(0)` no-op; pusta pula → bufor; niepusta → tylko indeks.
- `forfeit` nie podwaja orphana (`settle_position` przy cap = live ⇒ orphan 0, potem jeden `redistribute` pending).
- Cap `checked_sub(debt)` nadal fail-closed przy `cap < debt` (zły checkpoint).
- Cooldown nie dotyczy `claim` po `end_ts` ani Genesis.
- Flexible > 365 dni → `InvalidPeriod` on-chain, nie tylko UI.
- Feature `test-periods` skraca cooldown do 1 h; `compile_error!` mainnet + test-periods bez zmian.
- Izolacja vaultów, coverage ANL, split CAPY, roll w `claim`/`settle_expired` — bez regresji względem R5.
