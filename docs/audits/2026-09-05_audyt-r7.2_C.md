## A — Program ID / initialize pin

Poprawka zamyka wcześniejszy finding dotyczący możliwości zbudowania binarki z produkcyjnym Program ID bez przypiętego inicjalizatora.

Obecna macierz wygląda bezpiecznie:

```text
bez network feature               → TEST ID
test-periods                      → TEST ID
network-testnet                   → PROD ID + EXPECTED_INIT_AUTHORITY
network-testnet + test-periods    → PROD ID + EXPECTED_INIT_AUTHORITY
network-mainnet                   → PROD ID + EXPECTED_INIT_AUTHORITY
network-mainnet + test-periods    → compile error
network-mainnet + network-testnet → compile error
```

Wariant bez network feature nie może zostać przypadkowo wdrożony jako produkcyjny program `4Cpx…`, ponieważ ma inny `declare_id!`.

Zmiana testowego Program ID nie wpływa na PDA ani execution path buildów testnet/mainnet, ponieważ buildy sieciowe nadal używają produkcyjnego ID.

## B — Provenance / pack-audit.sh

`pack-audit.sh` działa teraz fail-closed i porównuje:

```text

```

To domyka scenariusz:


### Proceduralna uwaga na mainnet

Dla przyszłego `build-mainnet.sh` warto dodać bezpośrednio do release manifestu również:

```text

```

Nie jest to blocker dla obecnego R7.2, ponieważ aktualna zgodność została niezależnie potwierdzona z historii gita.


ponieważ środowisko nie miało Solana CLI ani samej binarki jako niezależnego artefaktu. Manifest deklaruje zgodność 1:1.

## C — CAPY supply 20M

Mainnetowa inicjalizacja CAPY wymaga:

```rust
#[cfg(feature = "network-mainnet")]
require!(
    state.base.supply == CAPY_TOTAL_SUPPLY,
    AnlError::InvalidCapySupply
);
```

`CAPY_TOTAL_SUPPLY` odpowiada:

```text
20_000_000 × 10^9
```

Jednocześnie wcześniej sprawdzane jest:

```text
mint_authority == None
freeze_authority == None
```

Po przejściu inicjalizacji podaż nie może zostać zwiększona.

Prawidłowa ceremonia:

```text
mint 20M CAPY
→ disable mint authority
→ disable freeze authority
→ init_capy_vault
```

Nowy `InvalidCapySupply` jest dodany na końcu enumu błędów, więc wcześniejsze kody błędów nie są przesunięte.

## Ważna uwaga przed mainnetem

Aktualny kod powinien być traktowany jako:

```text
finalny kod testnetowy
+
baza mainnetu
```

a nie jako finalny mainnet artefakt.

Przed mainnetem należy wykonać osobną ceremonię:

```text
final mainnet Program ID
+
EXPECTED_INIT_AUTHORITY = multisig
+
CAPY_TOTAL_SUPPLY = 20M
+
network-mainnet
+
bez test-periods
↓
build
↓
release manifest
↓
SHA .so
↓
deploy
↓
dump on-chain
↓
SHA dump == SHA .so
```

Jeżeli Program ID lub `EXPECTED_INIT_AUTHORITY` zostaną zmienione, powstanie nowy `src_tree`, który powinien dostać własny finalny provenance bundle.
